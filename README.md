# OCb-Backend-Trainee
Тестовое задание на вакансию [«Junior Python/FastAPI-разработчик»](https://hirify.me/jobs/1437178-junior-java-developer)

## Содержимое проекта
- `main.py` — точка входа в программу. Тут же находятся и обработчики URL-запросов («ручки»).
- `tests/integration_test.py` — интеграционный тест на добавление бронирования, затем поиск по ID, затем поиск по дате, и наконец отмены брони.
- `tests/test_post_booking.py` — модульные тесты на валидацию атрибутов бронирования (неправильные номер телефона, число гостей, даты).
- `service.py` — здесь расположен класс-сервис, в который приходят запросы из ручек. В нём инкапсулирован репозиторий. На ветке `main` это словарь (то есть, все данные хранятся лишь в памяти программы), а на ветке `SQL-based-service` это база данных SQLite (использует файл `database.db`).
- `exceptions.py` — собственные классы исключений для надлежащего абстрагирования работы сервиса и репозитория-хранилища бронирований.
- `models.py` — классы-модели для представления бронирования. `BookingCreate` для создания брони через ручку в Swagger, `BookingStore` для хранения в словаре (без идентификатора, но со статусом) и `BookingOut` для выдачи информации пользователю (со статусом и ид-ром в одном JSON).

Внутри словаря идентификатор бронирования является ключом, а не полем самого значения-бронирования, поэтому ID добавляется внутрь модели только для выдачи пользователю. В SQL-версии ид-ор хранится уже в `BookingStore`, а `BookingOut` отсутствует.

Для простоты валидации и безопасности, я решил поменять два поля в модели бронирования. Поле `booking_time` с типом `datetime.time` сделать `int` с диапозоном значений от 12 до 22. И поле `id` сделать `UUID`, чтобы решить проблему с генерацией идентификаторов ключей для словаря, заодно теперь злоумышленник не сможет узнать, сколько бронирований в системе всего, и не сможет последовательно получить к ним доступ.

## Как запустить (python pip)
Основная программа-сервер:
```
python -m venv ./.venv
python -m pip install -r requirements.txt
python -m fastapi dev
```

Тесты из корня репозитория: `pytest`.

Те же самые инструкции можно выполнить, перейдя на ветку `SQL-based-service`.
